### R04 が失敗した理由

- 利用者の依頼で、Android Auto のデベロッパーモードを ON にし、デベロッパー向け設定の「提供元不明のアプリ」に ☑（ほかの開発者設定は触っていない）
- 車につなぎ直しても一覧に出ない。logcat：`CAR.VALIDATOR: isPackageInstalledByPlayCheck service not connected` → `Package DENIED; failed all other checks [app.thetahatch.navi]`
- 同じ端末のメディアアプリ（Movie・Book・Music Hatch、Home から導入）は一覧に出る
- 公開の報告（AA 17.7〜17.9 の解析）では「提供元不明のアプリ」は Car App Library（TEMPLATE）のアプリを通さず、Play の所有の確認で通る。Google の公式文書では確かめていない
  - https://github.com/prototux/lapin/issues/1
  - https://github.com/AndreyPavlenko/Fermata/issues/846
  - https://github.com/mdc159/sierra-auto/issues/36
- インストール元の偽装・root は使わない

### DHU（2026-11-25 夕方、自宅）

- DHU 2.1（SDK の extras;google;auto r02.1、SHA-1 照合）を PC に入れ、AA の開発者メニューの「ヘッドユニットサーバー」→ `adb forward tcp:5277` で Tailscale 越しに接続。初回は AA の「ようこそ」（権限の同意）を利用者が続行
- 最初の接続の残りで AA の DHU サービスが「Already connected」で落ちた。AA を強制停止（車とは未接続）して起動し直すと投影が始まった
- DHU では Theta Navi Hatch が一覧に出る（DHU は AA の審査を飛ばすため。実車の R04 の代わりにならない）。**アイコンが白い丸**で絵が出ない → 直す候補
- 車側：800×400、可視域 [12,12][788,388]、Google のロゴつき実地図（夜の配色・建物の立体）、car_map_ready/loaded、map_only
- dualcheck：閉じる段は通過（車の地図は残り世代も不変）。開き直しで「Camera mismatch: latitude」。中心が約 75 m ずれ、倍率 18・傾き 45・向きは一致。両方の地図が SDK の現在地追従の表示で、追従の位置合わせ（パディングの違い）でずれている疑い。CameraLink の同期と dualcheck の判定のどちらを直すか要検討
- vehiclecheck（屋内）：Car API 8、正確な位置の許可あり。車 API・端末 GPS とも NO_CALLBACK_AFTER_30S
