# ユーザー要件の全体像
## 目的と操作
CX-8の非タッチ画面でGoogle Mapsの多数アイコンをダイヤル移動する手間を減らす。
車画面は地図中心、操作はズームとパン中心。地図をアクティブにして少ないクリックで操作したい。
検索、候補選択、経路、設定はナビ直下のタブレットでタッチ操作。
必要時に車と同じ場所をタブレットの別Viewで開きマルチタッチ。タブレットを閉じても車の地図は消えないこと。
独立閲覧と同期を切替。ズーム・パン以外の操作ボタンを車側から隠せる範囲を比較。案内に必要な曲がり角・距離等の情報は別。
AAの音楽+地図分割が固定かを実車で確認。AAホストUIは自作アプリから全面制御できる前提にしない。
既存Theta.Home.HatchはAA/CarPlay接続時だけ操作パネルを表示する将来案。ホームのソースはこのZIPに含まれない。

## 地図・検索・案内
最初はOSMを検討したが、現APKはGoogle Navigation SDKの実地図。OSM未使用であることを明記。
Google Maps相当の施設検索・交通情報・ルートを目指す。外部Google Mapsアプリ内部の経路抽出を必須手段としない。
Gemini APIキーで会話型地図検索。Geminiだけで地図SDK費用/キーを代替しない。
将来は経路計算、代替経路、渋滞再検索、経由地、走行案内、音声案内、音楽との共存、履歴・お気に入り。
車位置が使えるか、端末GPSとの差、OBD2/車速の可能性を調査。取得と測位改善/物理GPS由来を混同しない。
別スマホ（タブレットのSIMではない）への着信も車で受けたい。電話機能は独立の将来検証。

## 端末・接続
iPlay60 Pro（Pad Proではない）、SIM内蔵。CX-8は有線CarPlayのみ。
P2 Plus所有。小型CarPlay無線化アダプターは購入可との最新回答。
Plan B: タブレットをタッチ画面付きAI Box相当の送信側にし、車画面を地図専用の別ディスプレイとして使う。
CarPlay受信機化（タブレットにiPhone画面を出す）との方向取り違えを防ぐ。

## ユーザーの開発運用
1. 自宅PCでClaude Code Localを起動しRemoteから操作。
2. 車載タブレットでADBを有効にしTailscaleへログイン。
3. 自宅PCからTailscale経由で対象タブレットへADB接続。
4. 手元スマホからClaudeを操作。
5. このZIPをPCへ展開、APKインストールとログ収集・改修・再ビルド。
6. 画面とジョグ操作をユーザー協力のもと半自動試験。
単体/模擬/SDK/DHU/実車を分ける。APIキーは端末設定画面で入力。現車なしで実車合格を宣言しない。
